* Overview
The Flatpak's id is =io.github.nivaca.py-foliation= (=io.github.USER.REPO=:
Flathub checks that the repository exists). Its files:
- =packaging/flatpak/io.github.nivaca.py-foliation.yml= :: the manifest. Runtime
  =org.kde.Platform= 6.11 with the PySide6 base app (=io.qt.PySide.BaseApp=), so
  PySide6 is not built here. QtWebEngine and numpy are removed; QtPdf (the
  preview) and =packaging= (needed by pikepdf) are kept through the base app's
  cleanup, which would remove them.
- =packaging/flatpak/python3-deps.json= :: pikepdf and what it needs, as wheels
  with their checksums, for x86_64 and aarch64, at the versions of =uv.lock=;
  and uv_build, for the build only. Made by =tools/flatpak-deps.py --python 3.13=
  (the Python of the runtime: =flatpak run --command=python3 org.kde.Platform//6.11 --version=).
- =packaging/io.github.nivaca.py-foliation.metainfo.xml= :: the AppStream
  metadata (also installed by the RPM). Each release needs its =<release>= entry.

* Building and trying it here
#+begin_src sh
flatpak install --user flathub org.flatpak.Builder org.kde.Sdk//6.11 io.qt.PySide.BaseApp//6.11
flatpak run org.flatpak.Builder --user --force-clean --state-dir=build/flatpak-state \
    build/flatpak packaging/flatpak/io.github.nivaca.py-foliation.yml
flatpak run org.flatpak.Builder --run --state-dir=build/flatpak-state build/flatpak \
    packaging/flatpak/io.github.nivaca.py-foliation.yml py-foliation-gui
#+end_src
(=--install= instead of =--run= installs it for the user.) The sandbox sees the
home folder; files elsewhere are opened through the file chooser's portal.

The linter Flathub runs:
#+begin_src sh
flatpak run --command=flatpak-builder-lint org.flatpak.Builder manifest packaging/flatpak/io.github.nivaca.py-foliation.yml
flatpak run --command=flatpak-builder-lint org.flatpak.Builder builddir build/flatpak
#+end_src
The second says =appstream-external-screenshot-url= for a local build: Flathub's
builders mirror the screenshots themselves.

* Submitting it (once)
Flathub's submission guide: https://docs.flathub.org/docs/for-app-authors/submission
1. Fork https://github.com/flathub/flathub and branch from =new-pr=.
2. Copy the manifest and =python3-deps.json= to the root of the fork, and
   replace the =dir= source of the py-foliation module by the released tag:
   #+begin_src yaml
   sources:
     - type: git
       url: https://github.com/nivaca/py-foliation.git
       tag: v0.2
       commit: <the commit of v0.2>
   #+end_src
3. Open a pull request against =new-pr= titled =Add io.github.nivaca.py-foliation=.
   Reviewers may ask about =--filesystem=home= (the manifest says why).
4. Once accepted, Flathub makes the repository =flathub/io.github.nivaca.py-foliation=,
   which the author maintains from then on.

* Each release (after it is on Flathub)
In =flathub/io.github.nivaca.py-foliation=: update the tag and commit, and
=python3-deps.json= if =uv.lock= changed (=tools/flatpak-deps.py=), in a pull
request; Flathub builds it, and publishes it when it is merged. The release's
=<release>= entry must be in the metainfo of that tag.
